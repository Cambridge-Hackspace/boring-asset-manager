# Notifications

The **Notifications** page sends news to chat or other services: when stock runs low, when something is overdue, and other events you choose. Each channel says what it subscribes to, and you can send a test to check that it works. Deliveries that fail are retried. **Recent deliveries** shows what went where, and for a webhook what the receiver answered; **Deliveries** on a channel shows its own, and **Send again** sends a failed one once it is fixed. A channel that fails every attempt for a day is turned off, saying why; edit it to turn it on again.

Channels can go to **Discord**, to **email**, to any URL as a **webhook**, or to an **MQTT** broker, such as Home Assistant's. An MQTT channel publishes each event to a topic under its prefix, such as `bam/asset.hook/…` for a [hook](/help/hooks) triggered. Give it the broker's address as `mqtts://` to encrypt the connection, the user name and password the broker asks for, and, for a broker with a certificate of its own, its CA certificate.

A **webhook** posts each event as JSON to its URL, signed with a secret if you give one, so the receiver can check it came from BAM. It can send a body of your own instead, from a template. Addresses on a private network, such as `192.168.1.20` or this machine, are refused unless you tick **Allow private networks**, so that a webhook cannot be used to reach what sits behind BAM.
