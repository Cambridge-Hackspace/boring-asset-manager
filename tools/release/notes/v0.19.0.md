## NFC tags and long-range RFID

Assets can now carry **NFC tags**, which phones read with no app, and labels can carry **long-range RFID tags**, written by the printer as it prints. None of this has been tried on real tags, phones or RFID printers yet; reports are welcome.

### NFC tags
- **Write tag.** On an asset's page and its scan page, Chrome on Android writes the asset's scan link to a blank tag held to the phone, then offers to lock it. A phone held to the tag opens the asset, as its QR code does. Other browsers show the link to copy into an app such as NFC Tools.
- **Read tags on the Scan page.** In Chrome on Android, **Read NFC tags** listens while the Scan page is open and on screen. A tag holding this instance's link opens the asset in the app, from the offline copy too. A tag linking elsewhere, or holding nothing known here, says so.
- **A tag's serial number as a code.** An asset's new **NFC tag** code is a tag's serial number, read from a tag held to the phone or typed. It is kept in one form (`04:A2:3B:1C:5D:80:00`), found however it is typed, and carried by CSV, Excel and PDF exports and imports. A serial number identifies an asset; since tags can be cloned, it never authorizes anything.
- **The NFC mark on labels.** The label editor's action search (Ctrl+Enter) has **Add the NFC mark**, a contactless symbol showing where a label's tag is. It is our own drawing; the NFC Forum's N-Mark needs its trademark license agreement.
- **Help.** A new NFC tags topic covers which tags to buy (NTAG213, 215 or 216; on-metal tags for metal) and how phones read them.

### Long-range RFID
- **Encode tags while printing.** The `zpl` driver's new **RFID** option writes each label's tag before printing it, on Zebra's RFID printers, with a number of tries and what to do when a tag fails: skip the label, pause or error. A failed tag is printed VOID by the printer; BAM! doesn't hear of it.
- **What a tag holds** is set under **Admin → Printers → RFID tags**: the asset's code as text (the default), or GS1's GIAI-96 or GIAI-202 with your company prefix. An asset with no code the scheme can encode isn't printed, and says why.
- **Readers.** A handheld reader in keyboard mode, typing a tag into the Scan page, opens its asset.
- **The MCP server** reads and changes the RFID settings.
- [RFID tags](https://github.com/Cambridge-Hackspace/boring-asset-manager/blob/main/docs/rfid.md) has the details and sources.

### Upgrading
- **Back up first,** as always. This release adds no migrations, permissions or configuration.
- **Exports gain a `code.nfc` column,** after `code.code128`. Scripts that read export columns by position should read them by name.
