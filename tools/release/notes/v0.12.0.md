## Icons, and seeing where things are

This release gives bam icons: each category can have its own, drawn in isometric 3-D by [isolex](https://forge.axonibyte.com/axonibyte/isolex) (by Axonibyte Innovations, LLC, Apache License 2.0). They show across the interface and on labels. A place can then be drawn as a scene of everything in it.

Icons are optional. With no icon sources, bam looks and works exactly as it did. bam ships no artwork of its own except an "unknown" question mark.

### Drawing icons
- **A category's icon** is written in isolex source on the category's page, in an editor with:
  - syntax coloring;
  - errors marked as you type;
  - completion and snippets;
  - a live preview in light and dark.
- **Inheritance:** a subcategory takes its parent's icon, or extends it and changes one part.
- **Drafts:** a save that doesn't compile is kept as a draft, and the last good icons stay in use, so one bad edit never breaks the rest. Every published version is in its history, ready to restore.
- **The Icons page** (Settings → Icons) has:
  - a shared library;
  - the palette, with light and dark colors;
  - limits;
  - import and export of `.ilx` files as a zip;
  - a report of the icon names that nothing draws.

### Icons everywhere
- **In the interface:** icons appear in category badges, asset lists, an asset's page, scans and pickers.
- **An asset's own icon:** any asset can have its own icon instead of its category's.
- **As images:** `GET /api/v1/icons/image` draws an icon as SVG or PNG.
- **On labels:** label templates can print icons: the asset's own or a fixed one, shaded or outlined for thermal printers. They show the same in the editor's live preview and in print.
- **State:** an asset's icon shows when it is out of service, needs maintenance, is lent out, overdue, out of stock or running low, for icons that draw a variant for it. The **Start the state badges** button writes a starter set of badges.
- **Sizes from fields:** an icon's parameters can follow an asset's number fields, so a server with 2 in "Rack units" is drawn 2 units high.

### Scenes
- **See inside:** anything that holds things can be looked into. Its contents are drawn standing on its floor, each with its icon, and you can zoom, pan, choose things and step inside.
- **Show in place** opens an asset's location with that asset outlined.
- **Arrange** (for those who can edit) drags things into place a tile at a time and lifts them onto shelves and racks. Things that overlap are flagged, and every move is in the asset's history.
- **Save as SVG / PNG** downloads the scene as a picture.

### For assistants (MCP)
Assistants can write and check icon sources, draw icons, and bind parameters. For scenes, they can read one (`get_scene`), arrange it (`place_asset`) and draw it (`render_scene`). That lets them answer "where's the spare switch?" with a picture.

### Upgrading
- **Migrations:** `034` to `039` run when the service starts.
- **New permission, `icons.manage`:** it covers the library, palette and icon settings. Migration `035` grants it to every role that manages categories.
- **Compiler:** the isolex compiler (0.3.1) is embedded in the release binaries, pinned by checksum. A binary built from source without it (`tools/isolex/fetch.sh`) runs with icons switched off.
- **New Go dependency:** `github.com/tetratelabs/wazero`, which runs the compiler.
