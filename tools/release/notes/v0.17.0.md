## Forms of their own, hooks, and a choice of light or dark

This release changes how **flows ask things**. A Form now asks **its own questions**, and a new **Set fields** step decides which field each answer goes into. The editor **suggests the values** a step can use as you type, and **Add a step** describes each kind of step. What used to be called **actions are now hooks**, in the interface, the API and the docs. Screens no longer show **internal IDs**, and keys are derived from their labels. And the footer offers **Light, System and Dark**.

### Flows: forms and Set fields
- **A Form asks its own questions:** text, long text, number, date, yes/no, a choice of options it lists, or a photo. Each has a help line, a default, and whether it is required. Its key is derived from the question.
- **Set fields** is a new step. Each row picks a field that the flow's categories record, and the value to give it: an answer, any other value, or fixed text. It can also set the asset's photo. Before a Create, it fills in the new asset; after a Find or Create, it updates that asset. The editor says which it will do, groups the fields by category, and marks the fields a category requires.
- **Saving checks** that every field named exists, that fixed values suit their field, and that a Create gets every field its category requires. Change no longer sets fields; Set fields does.
- **Confirm** lists what Set fields will set.

### Flows: the editor
- **Values are suggested as you type.** Typing `{` in any template box lists the values available at that step: the four every run has, the flow's category, and what earlier steps set. The list narrows as you type. A **{ }** button lists them all. A name nothing sets before the step is flagged under the box before you save.
- **Only when** picks its value from those set before the step, and offers what suits it: a category, a choice's options, yes or no, a date, or text.
- **Add a step** is a menu that describes each kind of step, and works from the keyboard.
- **Choose category** offers every category the flow has, including ones added later, or only some, ticked.
- **A step's ID** ("Name") is gone from the editor. Steps keep the IDs they have.

### Hooks
- **Actions are now hooks.** A hook, such as Identify, is a button on an asset that tells something outside bam. Catalog has **Hooks**; a category has a **Links and hooks** tab; an asset has a **Hooks** card; a flow can **Trigger a hook**; and the permission is **Trigger hooks**. Old links to /actions still arrive.
- **The API and MCP are renamed outright.** See Upgrading.

### Keys and IDs
- **Keys are derived from their labels**, as field keys already were. This covers a flow's questions, a hook's key and a choice field's values. Each key is shown under its label with a **Change** button. Changing a key that something else relies on gives a warning.
- **A template's ID** has moved into a **Template** menu beside Save, as **Copy ID**.
- **Values kept from a former category** show the field's label, not its key.

### Light or dark
- **The footer** offers **Light, System and Dark.** System, the default, follows your device, as before.
- **Your choice** is saved on your profile, so it follows you to every device. It is also saved in the browser, so it applies before the page is drawn and when you are signed out.
- **The API** gains `PUT /api/v1/auth/theme`, and `/auth/me` carries `theme`.

### Fixed
- **Number questions** in a flow were sent as JSON numbers, which the server refused.
- **A Form's hidden fields with defaults** were never filled. Converted flows now fill them through Set fields. This may change what existing flows record (see Upgrading).

### Upgrading
- **Three migrations** run on start: 048 adds a theme to users, 049 renames actions to hooks in what is stored, and 050 converts every saved flow to forms and Set fields. Back up first, as always.
- **Flow runs part way through are ended** by migration 050. Anyone in the middle of a flow has to start it again.
- **Converted flows** ask the same questions under the same keys. A Set fields step before each Create files the answers into the fields they filled before.
  - **Hidden fields with defaults,** such as Owner = `{user}`, are now actually set.
  - **Flows that name a field they no longer ask about** may fail the new save checks the next time they are edited. The editor says which field and why.
- **Hooks replace actions in the API, with no old names kept.** Update anything that talks to bam when you upgrade:
  - **Routes:** `/api/v1/actions…` is now `/api/v1/hooks…`, and likewise under categories and assets. The old routes answer 404.
  - **JSON:** `action`, `actions` and `action_id` are now `hook`, `hooks` and `hook_id`.
  - **Devices** listening for the `asset.action` event must listen for `asset.hook`.
  - **The permission** `assets.act` is now `assets.hook`. Roles that granted it are converted.
  - **Notification channels** following `asset.action` are converted.
  - **MCP tools** are renamed: `list_hooks`, `save_hook`, `delete_hook`, `set_category_hooks`, `trigger_hook`, `hook_replies` and `reply_to_hook`.
- **Flow definitions** in the API are version 2. Version 1 is refused with a 400 that says what changed. Packages exported from earlier versions still import, converted.
- **A flow's photo question** can't be answered over MCP.
- **Backups** from earlier versions restore and migrate forward.
